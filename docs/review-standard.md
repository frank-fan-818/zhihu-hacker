# 审稿意见的判定标准

这份文档是"什么样的意见算切合实际、中肯"的正文，代码里的提示词与校验都按它实现。
改判据时先改这里，再改 `src/review-prompt.mjs`，最后跑 `test/review-prompt.test.mjs`。

## 1. 中肯的四条

| 要求 | 具体含义 | 在系统里的落点 |
|---|---|---|
| 说到点上 | 先点明这句话主张了什么，再指出缺的是哪一环；不写"不够严谨"这类空话 | 提示词要求理由里先写主张；服务端拒绝空话理由 |
| 能被接受 | 先承认作者已经做对的部分，只在真有缺口时报告；作者明说不主张的不算缺口 | 提示词限定五类缺口；本地规则沿用"否定/转述/提问"豁免 |
| 有用 | 给得出下一步方向，而不是只判死刑 | 每条意见带 `direction`（五选一） |
| 有分寸 | 分清关键缺口与可接受的取舍；不把风格偏好、修辞、口头语当论证问题 | 每条意见带 `severity` 三档，且允许用最低档 |

## 2. 判定三步

1. **这句话主张了什么？** 只是叙述、提问、明确说自己不主张（"我不确定""是不是"）的，不报。
2. **它是哪一类主张？** 按类型校准松紧，不搞一刀切：

   | 类型 | 松紧 |
   |---|---|
   | 事实类（可查证真伪） | 没有出处就值得报告 |
   | 价值判断类（应不应该） | 看是否自洽、是否交代取舍，**不要求它有出处** |
   | 个人偏好与口味 | 不报；被抬成事实主张时才按事实类处理 |
   | 预测类 | 看是否交代前提与不确定性，不因"可能不准"而报告 |

3. **缺口在哪？** 只报这五类，命中即报，越靠前越硬：

   1. 范畴错配（把不同范畴的对象放进同一论断，或让具体物件承担抽象结果）
   2. 因果缺失或倒置（把相关或并列说成因果，把结果当原因）
   3. 以偏概全（结论覆盖的对象、条件、时间超过材料范围）
   4. 数量或事实无出处（给了具体数字、比例、排名、权威结论却没交代来源）
   5. 与常识或领域共识冲突（需要额外依据才能成立，但文中没给）

同一句只报一次，报最硬的那一类。**宁可少报，也不为凑数报一行没有依据的意见。**

## 3. 每条意见的字段

| 字段 | 取值 | 缺了会怎样 |
|---|---|---|
| `quote` / `start` | 原文逐字片段及其位置 | 必须能回到原文；锚点不匹配直接判为无效输出 |
| `kind` | 五类缺口之一 | 必填 |
| `reason` | 主张 + 缺的那一环 + 为什么重要 | 少于 12 字或含空话词，**拒绝入库**，不会显示给作者 |
| `severity` | 关键 / 中等 / 轻微 | 可选；模型没给就不编 |
| `impact` | 影响核心结论 / 影响可信度 / 影响可读性 | 可选 |
| `direction` | 收窄范围 / 补充条件 / 补充依据 / 改为待核查 / 调整表述 | 可选；只给方向，**不允许替作者改写** |

严重度按"缺了这一环，结论还站不站得住"判定：关键=不补就不成立，中等=会被读者追问，轻微=值得顺手改。

空话黑名单（出现即视为没有给出原因）：不够严谨、不够准确、过于绝对、过于主观、缺乏说服力、有待商榷、存在问题、不严谨、表述不当、值得推敲、有失偏颇。

## 4. 复核（把材料与原句放在一起）的额外要求

- 先看清原句主张到什么程度，再看材料覆盖到什么程度，两者的差就是结论。
- 摘要只能支撑摘要本身能支撑的部分，不能因为"读起来像支持"就标成支持。
- **不为了显得平衡而硬凑正反双方**；没有反例就写"没有找到反例"。
- 材料不足或只与部分主张相关时，优先标 `unclear` 并写明局限。

## 5. 怎么验收

| 层面 | 手段 | 现状 |
|---|---|---|
| 提示词文本与理由校验 | `test/review-prompt.test.mjs`（不需要凭据） | 通过 |
| 离线规则行为 | `test/check-prompt.test.mjs` + `test/fixtures/check-samples.json` | 通过（12/12） |
| 真实模型质量 | `npm run verify:prompt` + `test/fixtures/prompt-samples.json` | **待模型凭据**；当前网关返回 401 |

`verify:prompt` 同时量两件事：判定准不准（命中/误报/漏报），以及意见中不中肯（有没有空话、有没有给方向与严重度）。只有两项都过才判为可用。

## 6. 已知边界

- 提示词约束的是模型行为，不是硬保证；判定质量仍取决于所选模型。换成较弱的模型必须重跑 `verify:prompt`。
- 本地规则（无模型时）只覆盖可判定的两类：范围强断言与范畴/单位错配。它不做语义理解，漏报是常态，面板文案已按此改写。
- 严重度是模型给的判断，不是校准过的概率；界面不把它呈现为置信度。
