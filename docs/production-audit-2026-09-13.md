# zhihu-hacker 生产就绪审计

> 此文保留修复前的审计证据；随后修复与最新验证见 [生产修复记录](production-remediation-2026-09-13.md)。审计测试已改为验证正确行为。

审计日期：2026-09-13。仓库：https://github.com/frank-fan-818/zhihu-hacker 。本地 HEAD 与远程 main 均为 `82d519c2ae4432ac0dc55ed8dc3fcbcf860d3014`。运行时 Node.js v24.13.0。

结论：当前是可运行的原型，尚不具备生产就绪条件。主要阻塞是用户输入可能丢失、部署实例间没有共享草稿存储、异步结果与身份状态缺乏完整原子性。现有测试通过，不能证明这些生产不变量成立。

## 方法与证据边界

主审负责仓库核对、基础验证、部署反例与裁决；三个子智能体分别负责安全红队、数据一致性红队、前端与发布审查。智能体交换候选并挑战前提。主审排除了“保存后旧建议仍可应用”的错误夹具假设：真实服务端会因版本变化拒绝；另保留了可达的“应用请求在途时继续输入”反例。

按以下第一性原理检查，而非按功能数量打分：

- 用户当前输入不能被未保存状态或异步响应静默覆盖。
- 返回保存成功的数据应在刷新、换实例及重新登录后可读取。
- 取消、删除、退出完成后，晚到结果不能撤销用户意图。
- 检查结果必须绑定实际被检查的文本；元数据变化不应破坏文本身份。
- 成本上限不能完全由调用者可替换的标识决定。
- 运维诊断不能修改正在运行的业务状态。

所有新增测试使用内存/临时数据库、隔离凭据与 fixture transport；没有对生产站点施压，没有使用真实模型或知乎额度，没有修改应用源码或部署配置。

证据类型：**本地真实代码复现**包括 HTTP、实际 Store/Service，以及 VM 中执行实际 app.js（最小 DOM/fetch 替身，非真实浏览器）；**受控交错**指在异步存储或写入边界暂停，验证某个时序的结果，不表示已经在公网或真实多进程压力下观测到；**静态部署风险**不冒充运行时故障复现。

## P1：上线前应解决

### 1. 匿名编辑未保存，却被标为干净并继续处理旧稿

- 位置：`public/app.js:64-68`、`:101-107`、`:147-150`。
- 触发：匿名用户完成第一次检查后修改正文，再检查或采用此前建议。
- 结果：saveDraft 不发送 PATCH，却把 dirty 清为 false；检查提交旧 revision。采用建议时返回的旧稿衍生文本直接覆盖输入框中的新段落。离开页面的未保存警告也被关闭。
- 证据：`test/audit-release.test.mjs` 前两项，执行实际前端函数。
- 修复方向：将“体验期内保存工作副本”与“长期保留/账号保存”分开。未同步文本时保持 dirty，禁止对旧稿继续执行或覆盖编辑器。

### 2. 登录成功不等于草稿跨实例可用

- 位置：`src/server.mjs:18-21`、`api/index.mjs:5-7`。
- 触发：实例 A 创建草稿，随后请求落在实例 B；或者承载草稿的实例被替换。
- 结果：共享登录仍然有效，但 B 返回草稿 404、项目列表为空。部署默认 SQLite 使用实例临时目录，无法兑现跨设备保留研究记录的产品承诺。
- 证据：`test/audit-runtime.test.mjs` 第一项，两个真实 HTTP 服务共享会话但使用独立数据库，同一 cookie 在 A 为 200、B 为 404。冷启动清理未在真实 Vercel 上执行。
- 测试盲点：原有 `test/vercel.test.mjs` 多实例登录测试给两个 handler 传入了同一个 SQLite 文件，掩盖了存储隔离。
- 修复方向：使用共享持久数据库，或明确采用单实例加持久卷的部署方式，并做备份恢复验证。
- 官方边界：[Vercel runtimes](https://vercel.com/docs/functions/runtimes) 将 `/tmp` 定义为 scratch space，不能当作持久数据库服务。

### 3. 数据库诊断会中断健康的业务任务

- 位置：`src/store.mjs:29-44`、`src/db-doctor.mjs:18`。
- 触发：任务处于 running 时，对同一数据库创建第二个 Store，或启动实际 db-doctor 进程。
- 结果：构造器无条件把所有 queued/running 行改为 failed/INTERRUPTED；原任务完成后无法写入检查结果。
- 证据：`test/audit-consistency.test.mjs` 包含第二连接测试和真实 db-doctor 子进程测试，均在临时库上复现。
- 修复方向：诊断连接必须只读；恢复逻辑使用工作进程租约/心跳，确认执行者已失效后再接管任务。

### 4. 任务最终提交绕过并发保护，可覆盖已保存稿或复活删除项目

- 位置：`src/service.mjs:165`、`src/store.mjs:50-55`。
- 触发前提：多个进程共享数据库，在最终 checkpoint 与 save 之间发生另一写入或删除。
- 结果：save 使用无条件 UPSERT，旧快照可以覆盖新 revision，也可以重新插入刚删除的项目；随后 saveOp 还可能重新创建其任务记录。
- 证据：`test/audit-consistency.test.mjs` 在最终写入前注入竞争编辑/删除，确定性复现。属于受控交错，不是实际双进程压力复现；单进程同步片段中没有同样的事件循环抢占窗口。
- 修复方向：项目存在性、owner、版本、任务未取消与结果写入放入同一个事务/条件更新；结果提交禁止 UPSERT。异步元数据也需要并发版本，不能只保护文本编辑。

### 5. 已登录用户在“采用修改”请求期间输入，新内容仍会丢失

- 位置：`public/app.js:147-150`。
- 触发：有效建议可应用，点击采用后，网络响应返回前继续在编辑器打字。
- 结果：编辑器未锁定，也没有输入代号检查；响应返回后无条件赋值 draft.value 并清除 dirty。
- 证据：`test/audit-release.test.mjs` 最后一项，模拟应用请求在途时输入；不依赖服务端接受过期建议。
- 修复方向：请求期间锁定相关编辑操作，或者比较请求发起时的编辑代号，保留新输入并提示合并。

### 6. 退出与登录最终写入存在竞态

- 位置：`src/oauth.mjs:101-108`。
- 触发：finish 已检查 logoutEpoch，但新的 session SET 尚未完成，此时 logout 完整执行，然后在途 SET 完成。
- 结果：退出后仍建立有效新会话；新 cookie 的 session 查询不再关联旧 cookie 的退出代号。
- 证据：`test/audit-security.test.mjs` 第二项，在异步存储写入处暂停复现。单进程异步或共享 Redis 下存在这种时序；未在真实身份提供方运行。
- 修复方向：使用原子条件会话提交，将退出代号与新会话绑定；提交时及会话使用时验证代号。

### 7. 匿名付费接口预算可通过替换 cookie 重置

- 位置：`src/server.mjs:24`、`:42`、`:63`、`:81-83`；操作预算另在 `src/service.mjs` 的 usage Map。
- 触发：固定 IP/session 发出 20 次问题查询，达到 429 后仅替换 cognitive_anonymous。
- 结果：下一次查询成功再次调用 provider。未发现应用级共享全局预算；攻击者还能不断建立匿名身份，多实例进一步放大额度。
- 证据：`test/audit-security.test.mjs` 第三项，本地 HTTP provider 调用数为 21。未消耗真实接口额度。
- 修复方向：增加共享总额度、并发限制和风险控制；匿名试用不能仅依赖可替换的 cookie。此发现是成本保护失效，不是读取他人草稿的越权。

## P2：正确性与防护缺陷

### 8. 登录入口永远不传待关联项目

- 位置：`public/app.js:187`。
- 匿名用户进入 startLogin 时 signedIn 恒为 false，`project && signedIn() && confirm(...)` 永不成立，发送 projectId:null。文字可以通过 pending 暂存，但来源、建议、检查历史与问题上下文不会随当前项目关联到账号。
- 证据：`test/audit-release.test.mjs` 第三项；后端迁移测试通过不代表前端调用正确。
- 修复：匿名当前项目应能明确选择迁移，并在登录返回后恢复项目身份与全部研究数据。

### 9. “暂时保留”使全部检查过期，重新检查又丢失保留状态

- 位置：`src/service.mjs:49-54`、`src/store.mjs:65-71`。
- defer 没有改文本却递增 revision；其他 findings 的 baseRevision 全失效。重新检查时旧结果因版本不匹配不能复用 deferred 状态。
- 证据：`test/audit-consistency.test.mjs` 第一项：两处检查中 defer 一处后，另一处修改请求报 STALE_FINDING，重查后原 deferred 变回 open。
- 修复：分离文本版本与记录并发版本，按未变化的原句身份保留用户决定。

### 10. OAuth state 单次消费不是原子操作

- 位置：`src/oauth.mjs:74-84`。
- 两个 finish 可同时读到 pending，再各自覆盖 consumed 并成功通过复查；单键 SET 原子不代表 GET/SET/GET 组合原子。
- 证据：`test/audit-security.test.mjs` 第一项，受控并发读取并使用两份 fixture 有效 code，得到两个新 session。
- 限定：真实身份提供方可能拒绝复用同一个 code；是否允许同一 state 对应两个有效 code 尚未联调。因此只证明应用的单次消费保证不成立，不声称账号接管已成立。
- 修复：使用原子 GETDEL 或 Lua 条件消费，且在消费前校验绑定关系。

### 11. www 页面放行，但同源写请求被拒绝

- 位置：`src/server.mjs:35`、`:59-60`。
- 配置 APP_ORIGIN 为主域时 www Host 可打开页面，但浏览器发送 www Origin 后创建草稿等写请求得到 403。
- 证据：`test/audit-runtime.test.mjs` 第二项，真实 HTTP 指定 Host/Origin。
- 修复：统一跳转到规范域名，或从同一份精确来源集合派生 Host/Origin 校验。

## 另一个上线阻塞：后台任务生命周期（静态证据）

`src/service.mjs:86` 用 queueMicrotask 发起异步任务，`src/server.mjs:108` 返回 202；函数入口没有 waitUntil 或持久队列来管理任务寿命。响应发送后能否继续跑完整模型/检索调用缺乏平台保证，前端可能持续轮询 running。

这是源码与平台契约不匹配的风险，未通过本地长驻 HTTP 测试证明 Vercel 实际冻结时刻。[Vercel waitUntil 文档](https://vercel.com/docs/functions/functions-api-reference/vercel-functions-package) 提供生命周期延长机制；它仍不能替代可靠持久队列、共享任务状态和失败恢复。

## 建议的修复顺序与验收

1. 先修复编辑器数据丢失和匿名体验/账号保存断层；用实际浏览器验证输入、采用、登录和刷新，包含请求期间打字。
2. 明确生产运行方式，补共享持久数据与任务执行保证；跨实例创建/读/写/取消/删除及重启恢复必须验收。
3. 将最终结果提交、state 消费、退出与会话建立改成真正原子协议；把受控反例转为断言正确行为的回归测试。
4. 修复诊断副作用、元数据版本、规范域名与共享预算。
5. 建立 CI、备份恢复演练、任务耗时/失败观测；再做真实知乎/模型成功链路与质量评估、负载和长时间运行验证。

本次没有执行真实浏览器端到端、真实 OAuth/模型联调、线上负载测试或备份恢复演练，不能给出这些维度的通过结论。
