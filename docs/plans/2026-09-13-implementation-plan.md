# 认知调试器 Implementation Plan

**Goal:** 在独立目录实现可本地运行的草稿检查、按需查证、修改采用和持久化闭环，接通官方接口适配层。

**Architecture:** 单进程 Node.js HTTP 服务提供静态前端及同源 API，SQLite 持久化项目、版本、操作和来源。操作异步执行并保存状态，浏览器轮询恢复；重启将未完成操作明确标为中断。外部提供方凭证仅来自服务端环境。

**Tech Stack:** 当前本机 Node.js 24.13、内置 node:sqlite/node:test、浏览器原生 JavaScript 与 CSS。此阶段使用原生前端，减少空项目依赖与部署复杂度。

## 审查结论

PRD v1.2 的用户行为和验收要求足够启动开发，但不是所有 P0/P1 同时完成的承诺。落实以下决策后开工：

1. 原稿版本与分析版本必须分别保护；保守使用完整草稿 revision 判断旧操作是否过期。
2. 暂不配置模型时可提供明确标为“本地规则初筛”的有限检查，不伪装模型或真实查证。查证缺少 Access Secret 返回未配置，绝不返回演示来源。
3. 模型适配采用服务端配置的 Chat Completions 兼容端点，实际提供方和凭证待配置；不读取其他项目秘密。
4. 本地单用户开发环境仍实现匿名会话隔离、同源写保护、输入长度限制、操作预算和版本冲突。
5. SQLite 仅用于单实例本地首版；公网多实例部署、OAuth、热榜、图谱、分享和新实验亮点不属于本次基础实现。
6. 查证操作内部使用 await Promise.allSettled 处理两类搜索，实际结果分别标注。默认每类一次，不隐式重试。
7. 一次生成只能引用当前项目返回的 source_id；确定性引用存在校验不能替代语义正确评测。

## 工作步骤

### 1. 领域与存储
- 创建 cognitive-debugger/src/domain.mjs、store.mjs。
- 测试：UTF-16 原句锚点、重复句子、版本冲突、精确摘录、非法引用。
- 完成条件：只修改指定范围，旧建议不覆盖新稿。

### 2. 提供方适配与操作
- 创建 src/providers.mjs、service.mjs、server.mjs。
- 测试：初筛零搜索、按需双源、部分失败、取消/删除迟到响应、幂等复用、重启中断。
- 完成条件：接口缺配置诚实返回；不能从其他会话读取项目。

### 3. 页面
- 创建 public/index.html、app.js、style.css。
- 实现草稿输入、近期项目、检查卡、来源侧栏、修改对照、全文检查、复制与下载。
- 视觉方向：编辑台/纸张审稿，暖白背景、深墨色文字、克制的蓝色批注；不做仪表盘式评分。

### 4. 验证与交付
- npm test 运行原生 Node 测试，node --check 检查脚本。
- 启动服务，在浏览器实际验证主流程、无凭证反馈、保存/刷新、手机宽度。
- README 记录启动、服务端配置、已实现范围与未验证项。
